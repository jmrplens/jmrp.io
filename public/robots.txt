# Content Signals (https://contentsignals.org/) — explicit intent: this site
# welcomes search indexing, AI input (RAG / grounding an answer), and AI
# training.
#
# Exactly three keys are defined by the specification: `search`, `ai-input` and
# `ai-train`. An earlier version of this file also declared `ai-retrieval`,
# which is not in the vocabulary — unknown signals are ignored, so it never did
# anything except suggest a stricter policy than the spec can express. Do not
# re-add keys that are not in the published list.
#
# The signal is REPEATED in every named group below, and that repetition is
# load-bearing rather than clutter. Under RFC 9309 a crawler obeys exactly one
# group — the most specific one that matches it — and ignores the rest,
# including `*`. With the signal declared only here, the ~30 agents that have a
# group of their own (GPTBot, ClaudeBot, PerplexityBot, Google-Extended…) were
# precisely the ones that never saw it: the opt-in was invisible to its own
# audience (GEO audit 2026-08-22, M6). The spec does not state whether signals
# are scoped per group; this assumes the conservative reading. When adding a
# new agent group, copy the line into it.
Content-Signal: search=yes, ai-input=yes, ai-train=yes
Allow: /

#                                     own URL. The llms.txt spec: "provide a

#                                     (URLs without file names should append

#                                     both locales.
#                                     Pages declare theirs with
#                                     rel="alternate" type="text/markdown", and
#                                     every page points at this index with

#                                     same pointer as a Link: header.
