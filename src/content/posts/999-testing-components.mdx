<StepByStep title="Deploying CSP">
<li>
**Configure Nginx**

Add the CSP header to your Nginx configuration file.
</li>
<li>
**Test with Report-Only**

Use `Content-Security-Policy-Report-Only` first to catch violations without breaking your site.

Review violation reports and fix issues in your code.

### DecisionTree

Interactive decision guides.

<DecisionTree question="Which CSP approach should you use?">
<details>
<summary>My site is completely static (no inline scripts)</summary>

Use `script-src 'self'` - the simplest and most secure option. No nonces or hashes needed.
</details>
<details>
<summary>I have a few inline scripts that rarely change</summary>

Use **hashes** (`'sha256-...'`). Generate the hash of each script and add it to your CSP.
</details>
<details>
<summary>My inline scripts change frequently or are generated dynamically</summary>

Use **nonces** with Nginx `sub_filter`. Generate a unique nonce per request.
</details>
<details>
<summary>I use webpack/bundlers that dynamically load chunks</summary>

Use **nonces + 'strict-dynamic'**. This allows dynamically loaded scripts to inherit trust.
</details>
</DecisionTree>

## Combined Examples

Using multiple components together for realistic documentation:

<Prerequisite title="Before You Start">
- Nginx installed and configured
- HTTPS enabled on your domain
- Basic CSP knowledge (see sections above)
</Prerequisite>

<TLDRSummary>
- Set `$cspNonce` from `$request_id`
- Use `sub_filter` to inject nonce into HTML
- Add nonce to CSP header
- Test with DevTools console
</TLDRSummary>

<StepByStep>
<li>
**Add nonce variable**

Set `$cspNonce` in your Nginx server block.
</li>
<li>
**Configure sub_filter**

Enable placeholder replacement for HTML files.
</li>
<li>
**Update CSP header**

Add `'nonce-$cspNonce'` to your `script-src` directive.
</li>
</StepByStep>

<SecurityRating rating="A+" title="Result" description="Following these steps will give you an A+ rating on Mozilla Observatory." />
