<h2>About This Tool</h2>
<p>
  Build cron schedule expressions using a visual interface with interactive
  field selectors. Click values to toggle them, use quick-pick buttons, or type
  expressions directly. The tool shows a human-readable description, previews
  the next 10 executions, and generates a ready-to-use crontab line.
</p>

<h3>Features</h3>
<ul>
  <li>
    <strong>Interactive field selectors</strong> — click individual values for
    minute (0–59), hour (0–23), day of month (1–31), month (1–12), and day of
    week (0–6) with visual toggle buttons
  </li>
  <li>
    <strong>Quick-pick helpers</strong> — "Every (*)" and "Clear" buttons per
    field for fast selection
  </li>
  <li>
    <strong>Bidirectional sync</strong> — edit the expression text and selectors
    update, or click selectors and the expression updates
  </li>
  <li>
    <strong>Smart expression generation</strong> — automatically detects step
    patterns (<code>{"*/5"}</code>), ranges (<code>1-5</code>), and lists (
    <code>1,15</code>) from selected values
  </li>
  <li>
    <strong>14 common presets</strong> — every minute, 5/15/30 min, hourly, 6h,
    12h, daily, twice daily, weekdays, weekly, monthly, quarterly
  </li>
  <li>
    <strong>Human-readable description</strong> — natural language translation
    of the expression with day and month names
  </li>
  <li>
    <strong>Next 10 executions</strong> — preview upcoming runs with relative
    times (in Xd Xh, in Xh Xm)
  </li>
  <li>
    <strong>Crontab line output</strong> — editable command field that combines
    with the expression for a ready-to-paste crontab line
  </li>
  <li>
    <strong>Copy &amp; share</strong> — copy the expression, the full crontab
    line, or a shareable URL with the expression encoded
  </li>
  <li>
    <strong>Inline syntax reference</strong> — expandable quick reference for
    <code>{"*"}</code>, <code>,</code>, <code>-</code>, <code>/</code> symbols
    and the field diagram
  </li>
</ul>

<h3>How to Use</h3>
<ol>
  <li>
    Click values in the <strong>Field Selectors</strong> to toggle them. Use
    "Every (*)" to select all values or "Clear" to deselect all.
  </li>
  <li>
    Or type a cron expression directly in the input field — selectors sync
    automatically.
  </li>
  <li>
    Check the <strong>human-readable description</strong> to verify the schedule
    matches your intent.
  </li>
  <li>
    Review the <strong>Next 10 Executions</strong> to confirm the timing.
  </li>
  <li>
    Edit the command in the <strong>Crontab Line</strong> section and copy the
    full line to paste into your crontab.
  </li>
  <li>
    Click <strong>Share Link</strong> to copy a URL that pre-fills the
    expression.
  </li>
</ol>

<h3>Special Characters</h3>
<ul>
  <li>
    <code>{"*"}</code> — matches <strong>any value</strong>.{" "}
    <code>{"* * * * *"}</code>
    runs every minute.
  </li>
  <li>
    <code>,</code> — <strong>list</strong> of values.
    <code>{"1,15 * * * *"}</code> runs at minute 1 and minute 15.
  </li>
  <li>
    <code>-</code> — <strong>range</strong> of values.
    <code>{"0 9-17 * * *"}</code> runs every hour from 9 to 17.
  </li>
  <li>
    <code>/</code> — <strong>step</strong> interval.
    <code>{"*/10 * * * *"}</code> runs every 10 minutes.
    <code>{"0 */6 * * *"}</code> runs every 6 hours.
  </li>
</ul>

<h3>Important Notes</h3>
<ul>
  <li>
    <strong>Timezone</strong> — cron uses the system timezone by default. Check
    with <code>timedatectl</code> or set the <code>TZ</code>
    environment variable at the top of your crontab.
  </li>
  <li>
    <strong>PATH</strong> — cron runs with a minimal <code>PATH</code>. Always
    use absolute paths for commands (<code>/usr/bin/python3</code>, not{" "}
    <code>python3</code>).
  </li>
  <li>
    <strong>Output</strong> — by default, cron emails output to the user.
    Redirect stdout and stderr to a file:
    <code>&gt;&gt; /var/log/myjob.log 2&gt;&amp;1</code>.
  </li>
  <li>
    <strong>Day-of-month + Day-of-week</strong> — when both fields are set (not
    <code>{"*"}</code>), cron uses <strong>OR</strong> logic: the job runs if{" "}
    <em>either</em> condition matches.
  </li>
  <li>
    <strong>Debugging</strong> — check <code>/var/log/syslog</code>
    (Debian/Ubuntu) or <code>/var/log/cron</code> (RHEL/CentOS) for execution
    logs.
  </li>
</ul>
