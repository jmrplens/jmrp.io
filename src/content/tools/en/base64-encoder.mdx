  - question: "Is Base64 a form of encryption?"
    answer: "No. Base64 is an encoding scheme, not encryption. It makes binary data safe to transmit as text but provides no confidentiality, since anyone can decode it instantly. Never use it to protect secrets."
  - question: "What is the difference between Base64 and Base64URL?"
    answer: "Standard Base64 (RFC 4648) uses + and / characters plus = padding, which can break inside URLs. Base64URL replaces them with - and _ and usually drops the padding, making it safe for URLs and JWTs."
  - question: "Is my data uploaded to a server when I encode a file?"

  - question: "Why is my Base64 output larger than the original file?"

<h2>About This Tool</h2>
<p>
  A multi-format encoder and decoder supporting the most common encoding
  schemes used in web development, APIs, and data exchange. Now with full
  file support for images, audio, video, documents, and any binary file.
</p>
<h3>Supported Formats</h3>
<ul>
  <li><strong>Base64</strong> — standard RFC 4648 encoding</li>
  <li><strong>Base64URL</strong> — URL-safe variant used in JWTs</li>
  <li><strong>URL Encoding</strong> — percent-encoding for URLs</li>
  <li><strong>Hexadecimal</strong> — hex string encoding</li>
  <li><strong>HTML Entities</strong> — HTML character escaping</li>
  <li><strong>Binary</strong> — binary string representation</li>
</ul>
<h3>File Support</h3>
<ul>
  <li>
    <strong>Images</strong> — PNG, JPEG, GIF, WebP, SVG (with preview)
  </li>
  <li><strong>Audio</strong> — MP3, OGG, WAV (with player)</li>
  <li><strong>Video</strong> — MP4, WebM (with player)</li>
  <li>
    <strong>Documents</strong> — PDF, JSON, plain text, and any other file
  </li>
</ul>
<h3>How to Use</h3>
<ol>
  <li>
    Switch between <strong>Text</strong> and <strong>File</strong> mode using
    the tabs
  </li>
  <li>In Text mode: paste text and select input/output encoding formats</li>
  <li>
    In File mode: drop a file or click to browse, then copy the Base64
    output
  </li>
  <li>Toggle the Data URI prefix for ready-to-use CSS/HTML embedding</li>
  <li>Use the Download button to save decoded Base64 back as a file</li>
</ol>
<h3>Privacy</h3>
<p>
  All encoding and decoding happens entirely in your browser. No files are
  uploaded to any server. Your data never leaves your device.
</p>

<h3>Linux Command Reference</h3>
<p>
  You can achieve the same operations from the terminal using built-in Linux
  tools. Here are the most common examples:
</p>

<h4>Text ↔ Base64</h4>
<TerminalSession>
  <TerminalSessionCommand>
    echo -n "Hello, World!" | base64
  </TerminalSessionCommand>
  <TerminalSessionOutput title="Base64 Output">
    SGVsbG8sIFdvcmxkIQ==
  </TerminalSessionOutput>
</TerminalSession>

<TerminalSession>
  <TerminalSessionCommand>
    echo "SGVsbG8sIFdvcmxkIQ==" | base64 --decode
  </TerminalSessionCommand>
  <TerminalSessionOutput title="Plain Text Output">
    Hello, World!
  </TerminalSessionOutput>
</TerminalSession>

<h4>Files ↔ Base64</h4>
<TerminalSession>
  <TerminalSessionCommand>
    base64 -w0 image.png > image.b64
  </TerminalSessionCommand>
  <TerminalSessionOutput title="Binary to Base64">
    (El comando genera el archivo image.b64 con el contenido en una sola línea)
  </TerminalSessionOutput>
</TerminalSession>

<TerminalSession>
  <TerminalSessionCommand>
    base64 --decode image.b64 > restored.png
  </TerminalSessionCommand>
  <TerminalSessionOutput title="Base64 to Binary">
    (Restaura el archivo original a partir de su representación Base64)
  </TerminalSessionOutput>
</TerminalSession>

<h4>Data URI para CSS / HTML</h4>
<TerminalSession>
  <TerminalSessionCommand>
    ```
    echo "data:$(file -b --mime-type logo.png);base64,$(base64 -w0 logo.png)"
    ```
  </TerminalSessionCommand>
  <TerminalSessionOutput title="Data URI Output">
    data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...
  </TerminalSessionOutput>
</TerminalSession>
