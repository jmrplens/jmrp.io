<h2>Acerca de esta herramienta</h2>
<p>
  Construye tramas Modbus RTU, TCP y ASCII válidas para la comunicación con
  dispositivos embebidos. La herramienta gestiona el cálculo de CRC-16 y LRC,
  cabeceras MBAP, interpretación de valores de registros, generación de tramas
  de respuesta y proporciona un desglose visual de cada byte de la trama con
  segmentos codificados por colores.
</p>

<h3>Características</h3>
<ul>
  <li>
    <strong>Tres protocolos</strong> — Modbus RTU (CRC-16), Modbus TCP (cabecera
    MBAP) y Modbus ASCII (LRC)
  </li>
  <li>
    <strong>11 function codes</strong> — Read Coils (01), Read Discrete Inputs
    (02), Read Holding Registers (03), Read Input Registers (04), Write Single
    Coil (05), Write Single Register (06), Read Exception Status (07),
    Diagnostics (08), Write Multiple Coils (0F), Write Multiple Registers (10),
    Read/Write Multiple Registers (17)
  </li>
  <li>
    <strong>Decodificador de tramas</strong> — pega tramas en hexadecimal para
    decodificar con autodetección de protocolo RTU/TCP, validación de CRC/LRC y
    detección de respuestas de excepción
  </li>
  <li>
    <strong>Interpretación de datos</strong> — decodifica datos de registros como
    Unsigned Int 16, Signed Int 16, Unsigned Int 32 o Float 32 con selección de
    orden de bytes (Big-Endian, Little-Endian, Mid Big-Endian, Mid
    Little-Endian)
  </li>
  <li>
    <strong>Constructor de respuestas</strong> — genera tramas de respuesta
    válidas para cualquier function code, incluyendo respuestas de excepción con
    todos los códigos de excepción estándar
  </li>
  <li>
    <strong>Ayuda de formato de datos</strong> — introduce valores decimales y
    conviértelos automáticamente a bytes hexadecimales, soportando uint16,
    int16, uint32 y float32
  </li>
  <li>
    <strong>Cambio de formato de dirección</strong> — alterna entre notación
    base 0, base 1 y notación Modicon (4xxxx, 3xxxx) con conversión automática
  </li>
  <li>
    <strong>Presets comunes</strong> — 8 ejemplos de tramas de carga rápida para
    pruebas instantáneas
  </li>
  <li>
    <strong>Formatos de copia</strong> — copia como hex con espacios, sin
    espacios, array de C o literal de bytes de Python
  </li>
  <li>
    <strong>Bytes codificados por colores</strong> — desglose visual con colores
    distintos para slave/unit, function code, datos, CRC/LRC, protocolo y
    segmentos de error
  </li>
  <li>
    <strong>Enlace compartible</strong> — URL compartible que codifica la
    configuración actual de la trama
  </li>
</ul>

<h3>¿Cómo uso esta herramienta?</h3>
<h4>Modo construcción</h4>
<ol>
  <li>
    Selecciona el modo <strong>Build Frame</strong> (por defecto)
  </li>
  <li>Elige el protocolo (RTU, TCP o ASCII)</li>
  <li>
    Configura la dirección del esclavo, el function code, la dirección de inicio
    y la cantidad
  </li>
  <li>
    Para funciones de escritura, introduce los datos en hexadecimal o usa la
    ayuda de formato de datos para introducir valores decimales/float
  </li>
  <li>
    La trama se genera automáticamente con CRC-16 (RTU), cabecera MBAP (TCP) o
    LRC (ASCII)
  </li>
  <li>
    Copia la trama en tu formato preferido usando los botones de copiar
  </li>
</ol>

<h4>Modo decodificación</h4>
<ol>
  <li>
    Selecciona el modo <strong>Decode Frame</strong>
  </li>
  <li>
    Elige el protocolo o usa <strong>Auto-detect</strong>
  </li>
  <li>
    Pega una trama en hexadecimal (p. ej., <code>01 03 04 00 0A 00 64 B2 62</code>)
  </li>
  <li>
    Pulsa <strong>Decode</strong> o presiona Enter
  </li>
  <li>
    Selecciona el formato de interpretación de datos (uint16, int16, float32,
    etc.) para ver los valores de los registros
  </li>
</ol>

<h4>Constructor de respuestas</h4>
<ol>
  <li>
    Selecciona el modo <strong>Response Builder</strong>
  </li>
  <li>Elige el function code para la respuesta</li>
  <li>
    Introduce los datos de respuesta en bytes hexadecimales, o selecciona{" "}
    <strong>Exception Response</strong> para construir una trama de error
  </li>
</ol>

<h3>Visión general del protocolo Modbus</h3>
<p>
  Modbus es un protocolo de comunicación serie desarrollado por Modicon en 1979
  para dispositivos industriales (PLCs, sensores, actuadores). Sigue una
  arquitectura maestro/esclavo donde el maestro inicia las solicitudes y los
  esclavos responden.
</p>

<h3>¿Cómo se calcula el CRC-16?</h3>
<p>
  Modbus RTU usa CRC-16 con el polinomio <code>0xA001</code>
  (forma reflejada de <code>0x8005</code>). El CRC se calcula sobre todos los
  bytes de la trama excepto el propio CRC, y se añade en orden{" "}
  <strong>little-endian</strong> (byte bajo primero, byte alto segundo).
</p>

<h3>¿Cómo se calcula el LRC?</h3>
<p>
  Modbus ASCII usa un Longitudinal Redundancy Check. El LRC es el{" "}
  <strong>complemento a dos</strong> de la suma de 8 bits de todos los bytes del
  mensaje (desde la dirección del esclavo hasta el último byte de datos). Se
  transmite como dos caracteres ASCII hexadecimales antes del CR LF final.
</p>
