<h2>Sobre esta herramienta</h2>
<p>
  Cada fichero de la bóveda es un sobre <strong>encrypt-then-MAC</strong>:{" "}
  <code>[ver][iv][hmacTag][cipher]</code>. Esta herramienta construye uno de
  verdad en tu navegador — deriva subclaves <code>encKey</code> y{" "}
  <code>macKey</code> distintas, cifra el secreto con{" "}
  <strong>AES-256-CBC</strong> y autentica juntos el byte de versión, el IV y el
  texto cifrado con <strong>HMAC-SHA256</strong>.
</p>
<p>
  Es la compañera interactiva del artículo{" "}
  <a href="/es/blog/011-encrypt-then-mac-vault/">Una bóveda con bloqueo ante fallos: Encrypt-then-MAC en un MCU</a>.
</p>

<h3>¿Cómo se usa?</h3>
<ol>
  <li>
    Escribe un secreto y una frase de paso, y fija el{" "}
    <strong>contexto autenticado</strong> (tipo de registro, slot, generación).
    El sobre se vuelve a sellar en vivo según escribes.
  </li>
  <li>
    <strong>Pulsa cualquier byte</strong> para alterarlo, o elige uno de los
    siete <strong>ataques</strong>: voltear un byte del cifrado/IV, falsificar el
    tag, truncar el cifrado, mover el fichero a otro slot, cambiar su tipo de
    registro o revertir su generación.
  </li>
  <li>
    Observa el <strong>veredicto de la lectura</strong>. Bajo encrypt-then-MAC
    todos los ataques <strong>se bloquean ante el fallo</strong> — y la
    herramienta te dice <em>por qué</em> falla cada uno (un motivo distinto para
    cada uno).
  </li>
  <li>
    Cambia el camino de lectura a <strong>descifrar-primero</strong> y pulsa{" "}
    <strong>Lanzar el ataque de oráculo de padding</strong>: un ataque de
    Vaudenay real recupera el último bloque del texto plano <em>byte a byte</em>{" "}
    usando solo la señal de padding válido/inválido — sin la clave. Vuelve a
    encrypt-then-MAC y el mismo atacante enmudece.
  </li>
</ol>

<h3>¿Qué muestra?</h3>
<ul>
  <li>
    <strong>Separación de claves</strong> — una frase de paso se convierte en una
    clave maestra que se abre en subclaves <code>encKey</code> y{" "}
    <code>macKey</code> distintas.
  </li>
  <li>
    <strong>Ligado al contexto</strong> — el tag cubre{" "}
    <code>ver ‖ recordType ‖ slotId ‖ generation</code>, así que reubicar,
    cambiar de tipo o revertir un fichero rompe el MAC aunque el cifrado esté
    intacto.
  </li>
  <li>
    <strong>Verificar antes de descifrar y bloqueo ante fallos</strong> — el tag
    se comprueba primero, así que un fichero manipulado nunca llega al descifrado
    AES-CBC y cualquier fallo no devuelve nada.
  </li>
  <li>
    <strong>El camino fatal</strong> — descifrar-primero corre el cifrado sobre
    los bytes del atacante antes del MAC, exponiendo un{" "}
    <strong>oráculo de padding</strong> real.
  </li>
  <li>
    <strong>Maleabilidad CBC</strong> — voltear un byte del IV voltea el byte
    correspondiente del texto plano del bloque 0 en la misma cantidad: la palanca
    del atacante.
  </li>
</ul>

<h3>La construcción, en fórmulas</h3>
<p>Sellado (camino de escritura):</p>
<pre><code>{`encKey = HMAC(master, "vault-enc")
macKey = HMAC(master, "vault-mac")
C      = AES-256-CBC-Encrypt(encKey, IV, PKCS7(P))
tag    = HMAC-SHA256(macKey, ver ‖ recordType ‖ slotId ‖ generation ‖ IV ‖ C)
file   = [ver] [IV] [tag] [C]`}</code></pre>
<p>Lectura bajo encrypt-then-MAC (verificar y luego descifrar):</p>
<pre><code>{`tag' = HMAC-SHA256(macKey, context ‖ IV ‖ C)
if not constant_time_equal(tag', tag): reject   // bloqueo ante fallos, sin texto plano
P    = unpad(AES-256-CBC-Decrypt(encKey, IV, C))`}</code></pre>
<p>Por qué el orden lo es todo — el trabajo al que se enfrenta un atacante:</p>
<ul>
  <li>
    Falsificar un tag sin <code>macKey</code>: una fuerza bruta de{" "}
    <code>2^256</code> (HMAC-SHA256) — inviable.
  </li>
  <li>
    Oráculo de padding (descifrar-primero): ~1 bit por consulta, ≤ 256 consultas
    por byte → un bloque de 16 bytes en ≤ ~4096 consultas.
  </li>
  <li>
    Encrypt-then-MAC elimina el oráculo de raíz: para un fichero falsificado el
    descifrado es <em>inalcanzable</em>, así que el ataque pasa de lineal a
    imposible.
  </li>
</ul>

<h3>Por qué la maleabilidad CBC es la palanca</h3>
<p>
  En CBC, <code>P_i = Decrypt(C_i) ⊕ C_(i-1)</code> (con{" "}
  <code>C_(-1) = IV</code>). Por tanto <code>ΔP_i = ΔC_(i-1)</code>: voltear un
  byte del bloque anterior — o del IV, para el bloque 0 — voltea el mismo byte
  del texto plano en la misma cantidad, de forma predecible. Ese cambio
  controlado es justo lo que permite a un oráculo de padding extraer el texto
  plano byte a byte.
</p>
