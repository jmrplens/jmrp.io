# CSP Violation Reporter

This script is a lightweight Node.js service designed to collect Content Security Policy (CSP) violation reports from browsers, log them locally, and notify via Telegram.

## Features

- **Detailed Notifications:** Sends formatted HTML messages to Telegram with icons and key violation details.
- **JSON Attachments:** Attaches the full original CSP report as a `.json` file to each Telegram message for deep analysis.
- **Local Logging:** Records every violation in `logs/csp-violations.log` for long-term tracking.
- **False-Positive Filtering:** Three-layer filter chain discards non-real violations before logging:
  - **Extension violations** — Reports originating from browser extensions (`chrome-extension`, `moz-extension`, `safari-extension`, etc.), including truncated source-file values.
  - **Browser-internal violations** — Reports from `about:blank`/`about:srcdoc` frames and `blob:` URIs generated by extensions or DevTools.
  - **Prefetch false positives** — Same-origin prefetch violations caused by browsers lacking `prefetch-src` support (falls back to `default-src`), including null source-file cases and `prefetch-src` effective-directive reports.
- **Rate Limiting:** Prevents notification spam by limiting reports from the same IP and for the same blocked URI to once every 10 minutes.
- **Security Hardened:** Implements request body size limits (10KB) to prevent memory exhaustion (DoS) and escapes HTML input.
- **Zero Dependencies:** Uses native Node.js `http` and `https` modules. Includes a built-in `.env` parser to avoid external dependencies.

## Setup

### 1. Environment Variables

The script requires the following variables in your `.env` file:

```bash
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=your_chat_id
CSP_REPORTER_PORT=58291 # Optional, defaults to 58291
```

### 2. Systemd Service

Create a service file at `/etc/systemd/system/csp-reporter.service`:

```ini
[Unit]
Description=CSP Violation Reporter Service
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/var/www/jmrp.io
ExecStart=/usr/bin/node scripts/csp-reporter.mjs
Restart=on-failure
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```

### 3. Nginx Configuration

To route reports to the service, add a location block to your Nginx site configuration:

```nginx
# CSP Report Endpoint (Proxy to local Node.js service)
location /csp-report {
    access_log off;
    proxy_pass http://127.0.0.1:58291/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

Then, update your `Content-Security-Policy` header to include the `report-uri`:

```nginx
add_header Content-Security-Policy "..."; report-uri /csp-report;" always;
```

## False-Positive Filters

The reporter applies three sequential filters before logging. If any filter matches, the report is silently discarded (HTTP 204 returned, no log entry, no Telegram notification).

### 1. Extension Violations (`isExtensionViolation`)

Detects reports originating from browser extensions by checking `source-file`, `blocked-uri`, and `document-uri` for extension protocol prefixes: `chrome-extension`, `moz-extension`, `safari-extension`, `ms-browser-extension`. Also matches the `<anonymous code>` source-file pattern used by Firefox for injected extension scripts.

Handles truncated values (e.g., `"chrome-extension"` without `://`) that some browsers report.

### 2. Browser-Internal Violations (`isBrowserInternalViolation`)

Catches violations from browser-internal contexts:

- **`about:` pages** — `source-file` or `blocked-uri` is `"about"` (from `about:blank`, `about:srcdoc` frames). These originate from extension-injected iframes, DevTools, or browser-internal scripts. This is typically the largest category of false positives (~57% in testing).
- **`blob:` URIs** — Generated by extensions or DevTools, not by page code.

### 3. Prefetch False Positives (`isPrefetchFalsePositive`)

Browsers that lack `prefetch-src` support (notably Firefox) fall back to `default-src` when evaluating prefetch requests. Since same-origin prefetches should be allowed by `default-src 'self'`, these reports are false positives.

Matches when:

- `effective-directive` is `default-src` or `prefetch-src`, AND
- `blocked-uri` is same-origin (starts with the site URL), AND
- One of:
  - `source-file` matches Astro's prefetch module (`/page.[hash].js`)
  - `source-file` is null/empty AND `blocked-uri` looks like an HTML page path (ends with `/` or has no file extension)

## Usage

Once running, you can test the reporter using `curl`:

```bash
curl -X POST https://yourdomain.com/csp-report \
  -H "Content-Type: application/csp-report" \
  -d '{"csp-report":{"document-uri":"https://yourdomain.com/test","violated-directive":"script-src","blocked-uri":"https://evil.com/test.js"}}'
```
